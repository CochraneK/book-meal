## 口径与纪律

- 数据来源：**只有书本抽取结果** `data/data.json`，不含 Web 查证、不含记忆推断。
- 地点入选条件：`lat` 或 `lng` 为空。按 `data/data.json` **原始抽取口径**：
  全库 563 个地点，已定位 533 个，**待考 30 个**。
- 口径差异：README / 报告里的地点总数是 `generate_report.build_scope('full')`
  补入衍生地点后的**展示口径**（数字由 `src/sync_readme.py` 派生写入 README）；
  这些衍生记录均已定位，因此两种口径的待考数相同。本表只用原始抽取口径，
  避免把衍生记录混进人工考据队列。
- 表中「出处章节」是原书分部章序 key（`p<部>-c<章序>`），用于回书核对；
  章节正文按版权红线不入库、也不写进本文件。
- **本表不填任何坐标、不填任何推断年份**。对「圣地巡礼」而言错误坐标比留空
  更有害；考据结论须标注来源层级（书本抽取 / 记忆 / Web）后才可回填。
- 地点排序：按书中提及章数降序（冷门地点优先），同频按地名排序；
  事件保持 `data.json` 原序。
- 「书中提及形式」来自 `mentioned_as`，抽取时偶尔会混入上下文短语，
  **不全是严谨别名**，仅作回书检索线索，不据此推断地望。

## 完成后怎么回填

1. 地点：逐条查证，把结论与出处写进 `data/geo_annotations.json`
   （`source` 字段必须区分来源）；
2. 事件：确认有书内依据后，按 `事件名: {year, source, note, approx}`
   写进 `data/manual_event_years.json`；`source` 必须标来源层级，
   通行说法而非书中明确纪年时置 `approx: true`；无依据则保持留空；
3. 跑 `python src/merge.py` → `python src/build.py --check` → 重建报告；
4. 重跑本生成器，队列自动缩短；README 数字由 `src/sync_readme.py` 同步。
