## 共享核心 `src/core/`（唯一真源）

阶段划分与章号换算此前在 `generate_report.py` 与 `perspectives_prep.py` **各存一份拷贝**，

现已收敛到 `src/core/`，**任何脚本需要阶段或章号换算都必须从这里 import**：

| 模块 | 职责 |
|---|---|

消费者：`generate_report.py` / `perspectives_prep.py` / `story_material.py` /
`verify_perspectives.py` / `verify_story_refs.py`。

`python src/verify_core.py` 守三件事：阶段回归（与 `core/baseline_phases.json` 逐格比对）、

### v2 信息架构改造（2026-10-17 第二轮）

第一版报告被判定为「数据脏、像数据库导出、没有吸收明察精髓」。根因不是功能不足，
而是**没有分类学、没有取舍、没有结论**。四处改造：

1. **类型归约**（`type_reduce.py`）：抽取时 agent 自由造标签，废土事件 47 种里「其他」占 43%，
   天才事件 84 种且大量「日常/医疗」斜杠拼接，地点在「室内/设施/建筑/机构」四个互相重叠的
   粒度间摇摆。归约成有限基类（事件 13 / 地点 12 / 关系 17），原始文本保留为证据。
   判定两级：先认原始类型（抽取者看过上下文，信号更可靠），仅当其为「其他/空/不可识别」时

## v3.1 挂入 HTML + 修既有死链（2026-10-18 第六轮）

用户问「你这个挂入 html 了吗」。此前长文只是 `docs/` 下的独立 Markdown，
与报告是两张皮。这一轮把它挂成报告第 10 个视图，并顺手修掉一个**早已存在、
但一直没人点出来**的既有 bug。

**挂入方式**：`src/md_to_html.py`（Markdown 子集 → HTML，不引外部库，保证离线）
把正文里的「第N章」变成 `<a class="ch-ref" data-no="N">`；`generate_report.build_story()`
在构建期拿 `chapters.json` 对每个 `data-no` 做越界检查，**越界直接 raise**
（宁可在构建时炸，不要在产品里静默失效）。视图内三段：口径面板 / 目录 / 正文。

**既有 bug：payload 的 `chapters` 字段是章节 key，不是索引。**
`data.json` 里 events/persons/relations/other/places 的 `chapters` 存的是
`tiancai-c126` 这种 key，`generate_report.py` 原样透传给前端，而前端的
`chapterById` / 阶段划分全部以整数 index 为键。后果是三处**不报错、只是安静地错**：

| 位置 | 症状 |
|---|---|
| 事件表「章节」列 | 渲染出裸 key `tiancai-c1`，点击无反应 |
| `renderPhaseBody` 的 `inPhase` | `i >= ph.s && i <= ph.e` 字符串与数字比较恒 false → **阶段事件表整张是空的** |
| 故事视图点「第N章」 | 查该章事件恒为 0 条 |

修法：payload 里所有 `chapters` 字段过一道已有的 `key2idx` 转成整数 index，
并在构建期加自检 5——`data_js` 里再出现 `tiancai-c` / `feitu-c` 就 raise。

**同轮修掉的另外三处**（都是查这个 bug 时顺带暴露的）：
1. `renderPhaseBody` 的阶段边界已由 Python 换成书中真实章号 `no`，
   而事件筛选用 index，两边不同口径 → 改为先 `idx2no` 再比。
   天才基本法索引 112 之后 `n = i - 3`，不修就会把事件算到相邻阶段。
   「共 N 章」也改成实数章节数，不再用 `ph.e - ph.s + 1` 减。
2. `gotoChapter()` 找的是 `.phase-seg[data-ch=…]`，而阶段段用的是 `data-ph`
   → 永远是 null，点人物卡里的章节 chip 只会切个视图、什么也不发生。
   改为直接弹该章事件（文案区分「长文引用」与「普通查看」两个来源）。
3. 「出场章节」chip 顺序不稳定（同一人物的章号可能 99 排在 221 后面），按索引排序。

**探针的假阳性（值得单独记）**：`probe_story_refs.js` 一度恒报 `PROBE-ERR`。
两个原因叠加——① 检测写的是 `/PROBE-ERR/.test(dom)`，而探针源码本身被注入页面，
dom 里永远含着这串字面量；② 提取正则用 `</div>\s*<script>` 当边界，
但 probe-box 是 JS append 到 body 末尾的，序列化后它后面是 `</body>`。
**教训：注入式探针既要检测 title 而不是整个 dom，也要给内容一个明确的结束哨兵。**

三轮探针（都是「点开才渲染」的内容，`--dump-dom` 静态拿不到）：
`probe_story_refs.js`（故事章号弹窗）/ `probe_phase_table.js`（阶段事件表）/
`probe_chapter_chip.js`（人物卡章节 chip）。

**做法上有三条硬约束**（这是与「写 15 篇文章」的区别）：

1. **正文不写数字，只写占位符**。`{{tc.ev}}` 这类占位符在渲染时从 `papers/_metrics.json`
   取实测值，改数据就改论文，手改正文的机会为零。渲染器遇到无法解析的键会**直接报错**——
   但 v3.11 开发中它一度静默返回 0：`gender_n` 根本没进指标表，13 号论文于是印出
   「可判定 0/221 人」。是 `verify_papers.py` 的①号闸抓住的（现算 14 ≠ 记录 None）。
   随后把「缺键即 0」改成只对 `tb/tbp/rb/appel` 这类计数表生效，普通标量缺键直接抛错。
2. **文献必须可点开**。`src/verify_refs.py` 逐条检索 Crossref，过四道闸（类型 / 标题 Dice ≥0.85 /
   年份差 ≤1 / 作者姓氏）才写进 `papers/references.json`，APA-7 由**元数据自动生成**而非手抄。
   第一版没有类型闸，命中率看着高，实际把书评当成了专著引（Foucault、Scott 1998、Bauman、
   Illich 的医学书全是「某书的评论」）——加类型闸后这四类全部落榜。
3. **人文经典不能靠 DOI 核验**。Crossref 里没有 1990 年前人文专著的原版记录（只有书评与重印本），
   OpenLibrary / Google Books / Wikidata 在本机网络环境下全部不可达（502 或空响应）。
   因此本项目的取舍是：**只保留能在 Crossref 定位到真实版本的文献**，无法核验的经典
   （Foucault、Hart、Genette、Tuan、Lefebvre…）改用同主题、有 DOI 的期刊文献替代

   取代 Foucault 与 Hart）。文献池因此只有 25 条，但每一条都能点开。

**校验**：`src/verify_papers.py` 六道闸——① 指标独立复算（并查集算连通分量，与

④ 引用闭合（正文（Author, Year）↔ 参考文献双向）⑤ 数字可溯源（正文里任何百分比/三位数
都必须能在指标集合里找到）⑥ 每条文献带 DOI。15 篇全过。
