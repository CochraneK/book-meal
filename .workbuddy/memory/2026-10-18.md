## 既有 bug（本轮最值得记的根因）
`data.json` 里 events/persons/relations/other/places 的 `chapters` 存的是章节 **key**
（`tiancai-c126`），generate_report.py 原样透传给前端，而前端 `chapterById` / 阶段划分
全部以整数 **index** 为键。三处**不报错、只是安静地错**：
1. 事件表「章节」列渲染裸 key，点击无反应；
2. `renderPhaseBody` 的 `inPhase` 用 `i >= ph.s && i <= ph.e`，字符串与数字比较恒 false
   → 阶段事件表整张是空的；
3. 故事视图点「第N章」查该章事件恒为 0 条。

修法：payload 所有 chapters 过已有的 `key2idx` 转 index，并加**构建期自检 5**
（data_js 里再出现 `tiancai-c`/`feitu-c` 就 raise）。
→ 这类 bug 的根治办法不是修完就算，而是让它**再也不能静默发生**。

## 同轮顺带修的三处
a. `renderPhaseBody` 阶段边界已被 Python 换成 no，事件筛选却用 index → 两边不同口径
   （天才 index 112 之后 n=i-3，会把事件算到相邻阶段）。改为先 idx2no 再比；
   「共 N 章」改实数章节数，不用 ph.e-ph.s+1 减。
b. `gotoChapter()` 找 `.phase-seg[data-ch=…]` 而阶段段用 `data-ph` → 恒 null，
   点人物卡章节 chip 只切视图、什么都不发生（安静的死按钮）。改为直接弹该章事件，
   文案区分「长文引用」/「普通查看」两个来源。
c. 「出场章节」chip 顺序不稳定（99 可能排在 221 后面），按索引排序。

## 探针假阳性教训（跨项目复用）
`probe_story_refs.js` 一度恒报 PROBE-ERR，两个原因叠加：
① 检测写 `/PROBE-ERR/.test(dom)`，而探针源码本身被注入页面，dom 里永远含这串字面量；
② 提取正则用 `</div>\s*<script>` 当边界，但 probe-box 是 JS append 到 body 末尾的，
   序列化后它后面是 `</body>`。
→ 注入式探针必须：**检测 document.title 而不是整个 dom**；给内容一个**纯文本结束哨兵**
（写成 HTML 注释会被序列化转义成 `&lt;!--…--&gt;`）。
