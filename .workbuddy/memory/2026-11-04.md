# 2026-11-04 · 重新改造项目：5 个孤岛 → 1 个书库产品

## 主题
用户「好好重新改造项目」并全选 4 个方向（产品体验重做 / 工程架构整理 /
还清路线图技术债 / 流水线标准化）。本轮主线定为**统一书单 → 门户重做 →
6 份报告注入书库导航条 → 把路线图声明变成机器可验断言**。

## 关键架构决定
- **书单单一真源** `src/book_registry.py`：`load_with_warnings()` 返回完整
  manifest + 派生 `href / kindLabel / _order`。`build_hub.py` 的
  `load_manifests / report_href`、`sync_readme.py`、导航条全部委托它，
  不再各解析一遍 manifest。
- **导航条用「幂等后处理注入器」而非改 4 条构建链**：本仓有 4 条互不相同的
  报告构建链，第 4 条（sanggan）还在私有仓；且 `refresh-index.yml` 会在 CI
  里重新生成并回写 standalone.html / ming/index.html / index.html，手改进产物
  必被覆盖。→ `src/sync_shelf.py`（`--check / --list / --quiet`），目标清单从
  manifest 派生，base 由产物深度自动算（`../../` / `../` / `./`）。
  `book_registry.inject_shelf()` 操作 bytes、跟随文件主流换行（本机
  autocrlf=true / CI LF），保证字节级确定性。
- `file://` 双击离线单文件时，导航链接自动改指线上书库
  （`BOOK_SHELF_ONLINE_BASE`），正文仍完全离线。
- `publish_books.py`：`canonical_digest()` 剥离导航条后再比对；写模式复制时
  直接注入，本地发布不丢条。跨子工程 import 用 `sys.path.append`（不是
  insert(0)，避免 teardown/src/core 被根 src/core 遮蔽）。

## 顺手修掉的真实 CI 隐患
- `publish_books.py --check` 把 `updated` 无条件写成「今天」，导致**发布后每过
  一天 CI 必报「平台副本落后」**（纯日历触发的假阳性）。改为：产物内容未变
  就沿用旧 `updated`，内容真变了才刷新为今天。
