## 追加（第四阶段）：系统性仓库整理（repo hygiene）

### 起因与诊断
用户反馈「不清楚全局，容易迷失在细节里」。实测根因是**四类东西混在同一目录**：
工作区 263.4 MB / 4069 文件，其中 `.git` 44.4 MB、受控文件仅 417 个 / 32.3 MB，
其余约 187 MB 全是不入库的本机文件。已用两张分层图向用户说明边界。

核查结论（避免误判）：
- `.gitignore` + `teardown/.gitignore` 的版权规则**已很严谨**（连「不能写 `*.txt`
  否则吃掉 requirements.txt」都写了注释），9 条私有输入 `git check-ignore` 全命中，
  **不需要补规则**——改成把它们变成 CI 断言。
- `papers_pilot/` 是独立 git 仓库：1392 文件、0 未提交、**无远程**、最后提交 2026-10-02；
  `.dump/git-sync/` 是另一个独立仓库（HEAD `75e3613`）。删了不可恢复，属资产不是垃圾。
- `teardown/out/` 是本机 `publish_books.py --check` 的输入，移走会让门禁报
  「产物不存在」→ **明确保留**（CI 干净 checkout 靠 quotes.json 缺失跳过，不受影响）。

### 改造
- 新增 `src/repo_hygiene.py`：把「哪些能归档、哪些碰不得」常量化。
  `--report` 分层体检 / `--archive` 非破坏移动（默认 dry-run，`--apply` 才动，
  `--restore` 按 manifest 一键回滚）/ `--check` CI 门禁。
  门禁用 `git check-ignore --no-index` 探针，**干净 checkout 文件不存在也能验规则**。
  支持**追加批次**：`__pycache__` 每次跑 Python 都再生，重复归档用时间戳后缀，
  既不覆盖上一批也能逐项回滚——清理是常态能力不是一次性动作。
- `src/sync_readme.py` 模板新增「仓库速览（不迷失版）」：四层表 +
  「改哪里 → 跑什么」+ 两条红线；质量门禁表与仓库结构列表同步。
  README 10154 → 11312 字符，`--check` 通过。
- `.github/workflows/ci.yml` 新增「仓库卫生检查（忽略边界 / 主体完整性）」，
  排在模块遮蔽巡检之后、compileall 之前。
