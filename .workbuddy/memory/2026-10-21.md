### 新踩的坑（都写进 MEMORY.md 了）
1. **`core.quotepath` 让中文名守卫视同虚设**：`git ls-files` 默认把中文路径输出成八进制
   转义，`| grep '明朝那些事儿'` 永远不命中——原来的版权巡检一直是纸糊的。
   现在巡检脚本显式 `git -c core.quotepath=false ls-files`。
2. **160 个分章正文差点入库**：`data/swdw/chapters/0001.txt…0160.txt`，纯数字文件名、
   单个 7KB，名单闸和体积闸都抓不住 → 加 `data/*/chapters/` 目录规则 +
   `data/**/*.txt`（后者覆盖散落在 `data/<id>/` 根部的 `source_combined.txt`）。
3. **gitignore 不能写 `*.txt`**：会吃掉 `requirements.txt`，CI 的 `pip install -r` 直接没。
4. **依赖本地私有数据的校验要「跳过」不是「判失败」**：`quotes.json`（金句）不入库，
   三个 gate 在 CI 上因此报假漂移。统一改成指标取 `None` + 打 `[SKIP]`。
5. **`publish_books --check` 的时间戳误报**：manifest 的 `meta.generated` 每次都变，
   导致 same → COPY。加 `canonical_digest()` 比对时忽略该字段。
6. **写死的 Windows 路径**：`generate_report.py` 的 NODE、`check_report.py` 的 find_chrome
   在 Linux runner 上 FileNotFoundError → 改成环境变量 → PATH → 常见位置三级探测。
7. **同步守卫**：CI 产物 0.93MB vs 仓库 0.96MB（缺金句）会被判「落后」，
   `publish_books.py` 现在在 quotes 缺失时跳过该书，而不是降级覆盖线上文件。
